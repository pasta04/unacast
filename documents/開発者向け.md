# 開発者向け

## 必要な環境

- Node.js 22.13 以上の 22 系、または 24 以上
  - ビルドに使っている vite 8 / electron-vite 6 / @electron/packager 20 と、ESLint 10 の要件による
  - GitHub Actions (CI) は Node.js 24.15.0 でビルドしている

## ビルド方法

```
git clone https://github.com/pasta04/unacast.git
cd unacast
npm ci
npm run buildwin
```

| コマンド | 内容 |
|---|---|
| `npm run buildwin` | Windows 向け (asar 形式)。`unacast-win32-x64` フォルダに出力される |
| `npm run buildwinunpack` | Windows 向け (asar なし)。配信画面の CSS などを直接編集できる |
| `npm run buildmac` | Mac 向け (asar 形式) |

## 開発時のコマンド

| コマンド | 内容 |
|---|---|
| `npm run dev` | 開発用に起動する。初回は Electron 本体がダウンロードされる |
| `npm run lint` | ESLint によるチェック |
| `npx tsc --noEmit -p .` | TypeScript の型チェック |

## リリース方法

1. `package.json` の `version` を上げて master にマージする (`npm version <バージョン> --no-git-tag-version` で `package-lock.json` も揃う)
2. GitHub の Actions で「Release」ワークフローを master で実行する (Run workflow)。入力はリリース名とリリースノート (Markdown)
3. ワークフローが Windows 版 (通常版・unpack 版) をビルドし、`version` と同じ名前のタグ (例: `0.9.0`。`v` は付けない) を付けたリリースを作成して、`unacast-win32-x64.zip` と `unacast-win32-x64_unpack.zip` を添付する

同じ名前のタグが既にある場合は、ビルドせずに失敗する。
既にあるリリースの zip だけを作り直す場合は、`reupload` にチェックして実行する (リリース名・リリースノートは変わらない)。

## 注意事項

### ビルドするマシンと異なる OS・CPU 向けにビルドする場合

VOICEVOX の読み込みに使っている koffi は、ネイティブのバイナリが OS・CPU ごとの別パッケージ (`@koromix/koffi-win32-x64` など) になっており、`npm ci` はビルドするマシンに合うものだけをインストールする。

GitHub Actions や Windows 環境で Windows 向けにビルドする場合は、そのままでよい。

ビルドするマシンと異なる OS・CPU 向けに作る場合 (例: Apple Silicon の Mac で `npm run buildmac` を実行する。アプリは x64 向けに作られる) は、対象のバイナリが入らず、作ったアプリが起動しなくなる。その場合は、対象の OS・CPU を指定してインストールしてからビルドすること。

```
npm ci --os=darwin --cpu=x64
npm run buildmac
```
